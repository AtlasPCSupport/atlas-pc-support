# Fase 3 — Capacidades Windows 10

Se conserva el dominio y el protocolo de publicación de la fase 2. Versión 1.2.0.
La compatibilidad se decide por build, edición, arquitectura y comandos disponibles;
no por el nombre comercial del registro ni por la presencia de PowerShell 7.

Cambios implementados:

- Perfil cliente x64 build 19044+; fixtures 19045 Home/Pro, 19044 Enterprise/IoT LTSC,
  Windows 11 y casos excluidos Server/x86/ARM64/compilaciones anteriores.
- Contratos de capacidades en las 27 entradas. El panel deshabilita con motivo y
  vuelve a comprobar al iniciar, también en la identidad elevada del proceso hijo.
- Windows 10 conserva DNS clásico. Cambiar DNS ya no activa DoH por registro. DoH
  exige Windows 11 y cmdlets disponibles; su configuración se deriva a Windows,
  sin inferir tráfico cifrado de una clave de registro.
- Personalización separa funciones de 11 y corrige la rama Search en Windows 10.
- Home/Device Encryption no se equipara a administración completa de BitLocker.
- Store pasa a comprobar/reparar registro existente en el usuario actual; diferencia
  falta de paquete, falta de registro, políticas y lectura no evaluada. No instala
  Store en LTSC ni altera políticas. App Installer se atiende por separado.
- Se retira el bootstrap WinGet de paquetes que mezclaba versiones móviles/fijas.
  El botón dirige al procedimiento oficial; no se instala automáticamente un módulo
  global ni se presupone que Store funcione para poder reparar App Installer.
- Perfiles/selecciones validan IDs y fuentes permitidas antes del proceso aislado;
  se bloquean opciones inyectadas y mínimos OS explícitos. La disponibilidad de una
  aplicación concreta sigue dependiendo del manifiesto WinGet vigente: no se afirma
  haber homologado las 52 aplicaciones del catálogo por heredar soporte de WinGet.
- Runtimes: perfil v14 separado de legado; NetFx3 usa Windows y puede indicar un
  origen matching `sources\sxs` sin requerir WinGet; estado/reinicio se muestran.
- Prefetch sale de la limpieza del instalador; las acciones de mantenimiento no se
  ejecutan como si fueran paquetes en una selección o perfil importado.

Fuentes: [DNS oficial de Windows](https://support.microsoft.com/en-gb/windows/experience/connectivity-networking/essential-network-settings-and-tasks-in-windows),
[WinGet/App Installer](https://learn.microsoft.com/en-us/windows/package-manager/winget/),
[registro de Store en el usuario correcto](https://learn.microsoft.com/troubleshoot/windows-client/shell-experience/troubleshooting-microsoft-store-apps-download-failure).

La evidencia de ejecución se añade en `FASE-3-EVIDENCIA-2026-10-24.json`. Las pruebas
de capacidades son fixtures; el host real es build 26100. La carga WPF crea ventana
y tarjetas sin ejecutar sus botones. No se han probado aún VMs 19044/19045, UAC de
otra identidad en esas VMs, medios físicos ni instalaciones de las 52 apps.
Por ello esta fase entrega implementación y regresiones, **no una certificación
Windows 10**. La matriz física/VM queda pendiente en el cierre del plan. Se mantiene
5.1 por defecto; no se declara PS7 homologado para todas las herramientas.
