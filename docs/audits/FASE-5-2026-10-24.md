# Fase 5 — Operación y entrega

Versión candidata 1.4.0. Se conservan el dominio, los pins independientes de
publicación, los releases completos y Defender activo. Esta fase no convierte las
pruebas en Windows 11 en homologación Windows 10.

## Implementación

- El merge automático queda limitado a Markdown de documentación del bot previsto.
  Se consulta el PR actual, diff completo y renombres; exige aprobación humana del
  mismo SHA, los tres jobs correctos y SHA/base sin movimiento antes del merge.
  La petición de merge incluye el SHA esperado. No ejecuta contenido de PR con el
  token de escritura. Una etiqueta antigua no autoriza cambios sensibles.
- CODEOWNERS explicita herramientas, GUI, Worker, tests y manifiesto. El build usa
  permisos de lectura y checkout sin credencial persistida. Las acciones oficiales
  checkout 7.0.1, setup-node 7.1.0, upload-artifact 7.0.2 y github-script 9.0.0 quedan
  fijadas por SHA después de consultar versiones y notas oficiales. Se mantiene
  Node 22 para los tests del Worker y sus dependencias fijadas; Node no es requisito
  del cliente Windows. Los jobs de build tienen límite de 20 minutos.
- Biblioteca de informes compartidos: redacción de claves, recuperación, rutas de
  usuario, SID, IP/MAC y correos; campos estructurados de identidad/serial y valores
  explícitos. JSON/HTML/texto incorporan herramienta, versión, commit, fecha UTC y
  alcance. Se integra en los escritores documentados en el manual de operación.
  Texto libre y salidas externas todavía requieren revisión antes de compartir.
- Entrega omite cuentas, seriales y secretos de recuperación; activación consulta
  estado nativo con timeout y código, sin certificar derechos. Checklist JSON
  persistente por ID, guardado inmediato, copia anterior y validación de esquema.
  Una confirmación manual necesita evidencia y fecha. El HTML es una instantánea
  sin «marcar todo» ni controles que aparenten guardar cambios sin persistencia.
- Licencias sustituye decodificación poco fiable y copias implícitas por inventario
  local redactado; `REVEAL` y `COPY` son decisiones separadas. No certifica M365 ni
  derechos por encontrar una clave. El módulo Wi-Fi deriva a ajustes de Windows y
  deja de extraer/exportar contraseñas.
- Monitor y consultas bajo demanda pasan a un runspace; WPF solo sondea resultados,
  limita concurrencia y solicita cancelación en timeout/cierre. No inicia lecturas
  hasta que el usuario las pide. Una prueba WPF con consulta lenta verifica que el
  inicio devuelve control y que el timer se detiene al cerrar.
- Tarjetas de las 27 entradas en español/inglés; búsqueda en ambos idiomas sin
  distinguir mayúsculas o acentos. Otros idiomas conservan cadenas generales del
  panel y fallback inglés para tarjetas. No se promete traducción completa de cada
  herramienta a siete idiomas.
- Inventario generado de herramientas/dependencias y comprobado en CI/local. Los
  README remiten a él; se retiran YAML duplicados de docs/ci, el bootstrap App
  Installer antiguo sin uso y la creación redundante de tareas DNS. Las tareas DNS
  heredadas se revisan manualmente; no se borran sin revisar su acción.
- Se añaden matriz de soporte, manual de operación/recuperación y cierre por A01–A18.
  MIT de Atlas no concede licencia de uso laboral o redistribución de proveedores.

## Comprobaciones

La evidencia numérica final está en `FASE-5-EVIDENCIA-2026-10-24.json`. El runner
ejecuta guardas, AST, roundtrip de herramientas, hashes, reconstrucción aislada,
documentación vigente, analizador y Pester en 5.1 y 7.6.6. La prueba de WPF no pulsa
acciones de reparación. Los procesos nativos reales de las regresiones son hijos
inocuos; las mutaciones del sistema se sustituyen por mocks.

Adicionalmente: 9 regresiones ejecutan el script real de política de merge con API
simulada; 21 tests del Worker; `npm ci`, auditoría npm sin vulnerabilidades y deploy
en seco. Tras CI se verifica el commit remoto completo, se promueve ese SHA y se
repite la entrada online/offline `-NoLaunch` y las comprobaciones HTTP del dominio.

La codificación del generador incluye BOM para su ejecución directa por 5.1; los
manifiestos y artefactos mantienen la canonicalización del protocolo existente.

Fuentes de actualización de CI:
[checkout 7.0.1](https://github.com/actions/checkout/releases/tag/v7.0.1),
[setup-node 7.1.0](https://github.com/actions/setup-node/releases/tag/v7.1.0),

La aceptación integral sigue dependiendo de la matriz VM/hardware, licencias y los
límites de cada criterio expuestos en el cierre. No se ocultan como «plan completo
certificado» por tener CI verde.
